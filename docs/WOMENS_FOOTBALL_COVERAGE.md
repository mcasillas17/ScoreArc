# Women's fútbol on ScoreArc

ESPN coverage audit · November 15, 2026 · ScoreArc baseline `08c4e2d` · E23 discovery

**Start with the NWSL and Liga MX Femenil as the US/Mexico pair.** Both have the data to take a fan from a match to a team, through its squad, and into a player's recent performances. The English Women’s Super League (WSL) is a strong third competition. Those three returned **48 populated club rosters, 1,327 roster entries, and 1,326 distinct ESPN athlete IDs**. ScoreArc's existing Go roster mapper accepted every row.

Across ESPN’s regional indexes, 45 women’s competition feeds returned a matching league slug and a scheduled or finished event. The [full inventory](#espn-competition-inventory) includes current leagues, older tournaments, qualifiers and college soccer.

The first engineering work is team identity and knockout rounds. The current seed generator proposes existing men's team IDs for every Liga MX Femenil club. Both pilot leagues also use quarterfinal labels that ScoreArc's bracket mapper drops. Fixing those two things is more important to these leagues than adding a new page template.

### Local verification

In a disposable copy of this commit, an audit harness mapped six finished matches (the three pilot leagues, Liga F, UEFA Women's Champions League and the 2023 Women's World Cup). All six passed the Go summary identity/year, final-score and participation checks. The standings, sample roster, goals and assists boards also mapped for all six.

The Go source adapter also read the rolling scoreboard and its full-season window without a partial/error result. Rolling/full-window counts were NWSL **30/246**, Liga MX Femenil **45/134**, and WSL **42/182**. These measure published matches at probe time, including scheduled ones.

The harness applied existing migrations through 0028 to one disposable Postgres 16 instance. For **each pilot league**, it wrote the competition, distinct test team IDs, full standings, one squad and one match with detail using the ingester role. It then exercised the HTTP router using the SELECT-only reader role. Season matches, standings, team, squad, player and match detail all returned populated HTTP 200 responses (**18/18**). The returned squad sizes matched ESPN. This tested the existing write/read contracts with temporary pilot config. The full 48-roster check was a mapper check. Production capacity, finalization over time, historical completeness, reader-to-ESPN parity and visual rendering remain rollout checks.

[US league index](https://sports.core.api.espn.com/v2/sports/soccer/leagues?limit=1000) · [UK index](https://sports.core.api.espn.com/v2/sports/soccer/leagues?limit=1000&lang=en&region=gb) · [Mexico index](https://sports.core.api.espn.com/v2/sports/soccer/leagues?limit=1000&lang=es&region=mx)

**How to read the counts.** Teams counts the provider's team directory (`/teams?limit=500`), which can differ from entrants in an edition. Table counts entries in the standings response scoped to the sampled provider season year. A dash means no table entries were returned. Roster counts identified players in **one** team response, independent of the linked event. The linked roster identifies the team sampled. Historical matchday squads require evidence from the match itself. A zero means the sampled response was empty. Event dates are UTC. The “sched.” label marks an event ESPN had scheduled at the time of the probe. Historic rows can be useful even where a future edition has yet to appear.

Match each returned team ID and provider year. Then open one athlete’s profile, overview and bio.
