# Women’s fútbol on ScoreArc — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring all 45 audited women’s feeds, their identifiable teams and players, and every verifiable edition to the shared ScoreArc matchday. Establish current coverage first. Release historical editions in waves.

**Architecture:** The TypeScript registry describes competitions, edition publication and supported resources, and its generated JSON drives Go. The existing leased ingester writes canonical entities to Neon, the read-only Go API serves them, and the Next.js site uses its existing DataStore seam. Current matches get scheduling priority over archive imports.

**Tech Stack:** Next.js App Router, React, strict TypeScript, Vitest, Go 1.26+, PostgreSQL, Fly.io, R2 and the existing Vercel deployment.

**Spec:** [Approved design](../specs/2026-11-15-womens-football-and-shared-matchday-design.md) · [ESPN inventory, match IDs and edition evidence](../../WOMENS_FOOTBALL_COVERAGE.md) · [E23 dependencies](../../PRODUCT_ROADMAP.md#e23--global-competition-onboarding)

## Global constraints

- Keep EN and Mexican Spanish, the existing team URLs and follows, and the ESPN default with the staged reader cutover. Run a compound read against one source, including fallback. Keep route telemetry.
- **All · Women · Men** and **Todo · Femenil · Varonil** share the same brand-green active underline. Use “match” in English UI. Gold retains its existing prize and qualification meaning.
- Publication, eligibility for polling, and the last observed state of data are separate decisions. Candidate editions make zero public calls. New archives are readable year-round and make zero automatic live, roster-refresh or alert calls.
- Use the existing E18/T23.5 owner decision for the fields, assets, collection, retention and public uses of each cohort. Synthetic tests and existing authorized captures can establish engineering behavior. Run new upstream collection and promote only within the documented scope. A scores-only release is valid.
- Start implementation slices from updated main on feature branches. Re-read the files below against the current checkout. Keep the PRs independently reviewable and integrate through the normal release path. Preserve the ingester’s pooled write DSN, dedicated direct lease connection, read-only reader and finalized-match guards.

## Review focus

1. A hidden competition can still leak through a known match UUID, OG card, direct season URL or seed job. Exercise all four paths in tasks 1–3.
2. Two América teams share a name and crest. One athlete or club may also appear legitimately in multiple competitions. Test both separation and reuse in tasks 3, 6 and 9.
3. A busy men’s matchday, duplicated events or a failed women’s feed can hide matches or produce a false “no matches” headline. Test selection order and failures in task 7.
4. A knockout-only cup or closed edition with an active provider roster can show the wrong people and still return HTTP 200. Test membership provenance, season bounds and archive-only detail in tasks 4, 6 and 15.
5. A capped month, equal kickoff times across pages or a restart just after a final is written can silently lose or duplicate history. Exercise all three in tasks 12 and 14.
