# Reader API — Team Profiles, Squads and Team Fixtures Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give E4 (team pages) a backend. Today the reader can tell you a club's rank in a table and nothing else — not its location, not its colours, not who plays for it, not when it plays next. This plan adds four competition-scoped team endpoints and the two tables that back them, and it does so with one rule above all the others: **a statistic the provider did not send serializes as `null`, never as `0`.**

**Architecture:** Two new tables. `team_season` holds the per-(competition, season, team) record ESPN publishes on `/teams/{id}`; `squad_player` holds one row per athlete with that athlete's season statistics as a `jsonb` blob. The blob is deserialized into a struct of `*float64` fields, so a key ESPN omitted has no landing place and stays `nil` — absence maps to `null` with no defaulting code anywhere. `/teams/{teamId}/matches` does not get a second match query: `MatchFilter` grows a `TeamID` field and one more placeholder predicate, which is also how the team profile finds its next fixture.

**Tech Stack:** Go 1.26, chi v5, pgx v5, kin-openapi, testcontainers-go (Docker required).

## Global Constraints

- Extend the existing layering. Routes register in `App.router()`; handlers live in `handlers_teams.go`; SQL lives in `store_teams.go`; the `readerStore` interface in `server.go` is the seam and `fakeReaderStore` in `server_test.go` implements it. **Adding a store method means editing all three.**
- **No string-built SQL.** Every value is a pgx placeholder. The one non-placeholder fragment (`ORDER BY`) is selected from a package-level constant map keyed by an already-validated enum.
- **400 messages are built only from string constants in our own code.** Never `err.Error()` on a dependency error — `TestDependencyErrorsAreSanitized` exists because that leak class is real. Errors returned by `params.go` *are* our own constants and are safe to echo.
- Every new endpoint goes into `backend/reader/openapi.yaml`. `openapi_test.go` enforces: every object schema's `required` list equals its full property list, every object schema sets `additionalProperties: false`, every `GET` documents 200/405/500 (+429 off `/healthz`), and every response — 200 and error alike — declares a `Cache-Control` header. Because `required` must list every property, **no response struct may use `omitempty`**.
- Rate limiting is unchanged: `a.rateLimit` is router-level middleware and every new route inherits the 10 rps / burst 30 per-IP token bucket automatically. Only `/healthz` is exempt. **One request costs one token regardless of how much it returns**, which is exactly why the caps below are enforced server-side rather than left to the caller — a 35-row squad and a 500-row fixture list cost a client the same single token.
- Any new migration must be appended to **both** hardcoded file lists (`backend/reader/migrations_integration_test.go`'s `TestMigrationsRoundTrip` and `newIntegrationStore` in `store_integration_test.go`) and must have a working `.down.sql`. The round-trip test asserts **zero tables and zero roles** survive a full rollback.
- Gate before a PR, from `backend/`: `go build ./...`, `go vet ./...`, `go test -race ./...`. **Docker must be running** — the reader's store and migration tests use testcontainers.

## Ingester prerequisites

This plan writes the read path only. None of these endpoints return anything until
the ingester populates the new columns and tables. The write path is a sibling
slice; what it must persist is fixed here so the two agree:

1. **`team.location`, `team.color`, `team.alternate_color`, `team.venue_name`** —
   from `/teams/{id}` (`location`, `color`, `alternateColor`, and the venue name
   under the team's `venue` block). All four are nullable and must be written as
   `NULL` when absent, never as `''`. An empty string renders as a blank line on
   the page; `NULL` renders as nothing at all, which is the truth.
2. **One `team_season` row per (comp, season, team)** — from `/teams/{id}`'s
   `standingSummary` and `record.items[]`. ESPN gives `gamesPlayed`, `points`,
   `pointDifferential`, `pointsAgainst` and a `summary` string like `"2-1-0"`.
   `record_summary` is that `summary`; `points_for` is
   `pointsAgainst + pointDifferential`, and **if either operand is absent, write
   `NULL` rather than treating the missing one as zero** — a computed number with
   an invented operand is worse than no number.
3. **One `squad_player` row per athlete** — from `/teams/{id}/roster`. **One
   roster request covers all 35 players**, so a complete squad statistics table
   costs one upstream request, not 35. Walk
   `statistics.splits.categories[].stats[]` and look each statistic up **by its
   `name`, never by array index**: the category set and the stat set differ by
   position (a goalkeeper's `goalKeeping` category carries stats an outfielder's
   does not), so index 4 is a different statistic for different players. A name
   that is absent must produce an absent JSON key, not a zero.
   Note this shape differs from the match summary's flat `stats[]` — the roster
   nests one level deeper. Do not reuse the match extractor unmodified.
4. **`squad_player` DELETE.** The migration grants it because a squad changes:
   a transferred player's row has to go, and leaving it means the page shows a
   player who left. `team_season` gets no DELETE — its rows are upserted per
   (comp, season, team) and never removed.

**Not persisted, deliberately:** `nextEvent` from `/teams/{id}`. The profile's
next fixture is derived from the `match` rows we already hold, so it cannot
disagree with what `/matches` says about the same fixture.

**Not persisted, and not a field:** injuries. Each athlete on
`/teams/{id}/roster` carries an `injuries` array and it is **empty for all 35
players**. The field existing is not the data existing. There is no injuries
endpoint, no injuries column, and no `injuries: []` in any response — an empty
array would tell a caller we checked and the squad is fit, which we did not and
cannot.

| `/teams/{id}/matches` with no `range` | the club's season — at most 2×(N−1) league fixtures plus cup ties. **Data, not user input** | — |

## Empty versus missing — the rule these four endpoints follow

**404 when returning success would mean inventing an entity. `[]` when emptiness
is itself a fact about a well-formed question.**

- `/teams/{teamId}` on a club that does not play in this competition season →
  **404 `"team not found in this competition season"`**, not an object with null
  fields. A club can exist in `team` and not be in this competition: América are
  in Liga MX *and* the Leagues Cup with different records in each, which is why
  every route in this plan is competition-scoped.
- `/teams/{teamId}/squad` with zero `squad_player` rows → **404 `"squad not
  available for this team"`**, not `[]`. An empty array claims a football club
  has no players. It never does; what it means is that we have not ingested the
  roster yet, and a caller must be able to tell those apart.
- `/teams/{teamId}/matches` with zero rows → **`[]`**. A club with no fixtures in
  a window is a real state — the fixture list is not published yet, or the window
  is out of season. A caller that needs to distinguish "no fixtures" from "wrong
  team id" asks `/teams/{teamId}`, which 404s.
- `/teams` with zero rows → **`[]`**. A competition season we hold no standings
  for is a real state, and the existing `TestNilListDependenciesStillEncodeArrays`
  covers it.

```sql
-- Team identity that is not competition-specific lives on `team`: a club's
-- location, colours and home ground do not change when it enters a second
-- competition.
ALTER TABLE team
  ADD COLUMN location        text,
  ADD COLUMN color           text,
  ADD COLUMN alternate_color text,
  ADD COLUMN venue_name      text;

-- Everything that DOES change per competition lives here. América are in Liga MX
-- and the Leagues Cup at the same time with a different record in each, so the
-- primary key has to carry the competition and the season.
CREATE TABLE team_season (
  comp_id          text NOT NULL,
  season_id        text NOT NULL,
  team_id          text NOT NULL REFERENCES team(id),
  standing_summary text,
  record_summary   text,
  games_played     int,
  points           int,
  points_for       int,
  points_against   int,
  updated_at       timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (comp_id, season_id, team_id)
);

-- One row per athlete per competition season. `stats` is the athlete's season
-- statistics as ESPN sent them, key by key: a statistic ESPN did not send has no
-- key here, and the reader deserializes into pointers so absence stays null.
-- Storing a fixed column per statistic would force a NOT NULL DEFAULT 0 or a
-- nullable column per stat; the blob keeps "not sent" and "sent as zero" apart
-- for free.
CREATE TABLE squad_player (
  comp_id    text NOT NULL,
  season_id  text NOT NULL,
  team_id    text NOT NULL REFERENCES team(id),
  player_id  text NOT NULL,
  player     text NOT NULL,
  position   text NOT NULL DEFAULT '',
  jersey     text,
  stats      jsonb NOT NULL DEFAULT '{}',
  updated_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (comp_id, season_id, team_id, player_id)
);
-- E5 (player pages) reads one player across competitions; without this index
-- that is a sequential scan of every squad we hold.
CREATE INDEX squad_player_player_idx ON squad_player (player_id);

-- Both new tables inherit SELECT for scorearc_reader and SELECT/INSERT/UPDATE
-- for scorearc_ingester from the ALTER DEFAULT PRIVILEGES in 0001_init, so only
-- the extra privilege is spelled out. Squads need DELETE because a transferred
-- player's row must disappear; team_season rows are upserted and never removed,
-- so it gets no DELETE.
GRANT DELETE ON squad_player TO scorearc_ingester;
```

### Task 2: `MatchFilter.TeamID` — one match query, not two

**Files:**
- Modify: `backend/reader/store.go`
- Test: `backend/reader/store_integration_test.go`

**The renumbering, spelled out.** `matchesSQL` today binds `$1 comp`, `$2
season`, `$3 from`, `$4 to`, `$5 state`, and each value in the `matchOrderSQL`
map ends `LIMIT $6`. The team predicate takes `$6`, so **every `LIMIT $6` in
`matchOrderSQL` becomes `LIMIT $7`** and the argument list to `s.db.Query` gains
`teamID` between `state` and `filter.Limit`. Get this wrong in one direction and
the limit is compared against a team id; get it wrong in the other and the team
filter silently becomes the row cap. Neither errors — both return wrong data.
There are exactly two map values and one `Query` call; change all three.

```go
package main

import (
	"context"
	"errors"

	"github.com/jackc/pgx/v5"

	"github.com/mcasillas17/scorearc-backend/shared/espn"
)

// The club list comes from `standing` because that is the one table that says
// authoritatively which clubs are in a competition season. Ordering matches
// standingsSQL so grouped competitions do not interleave: rank 1 of Group A and
// rank 1 of Group B are both rank 1, and sorting on rank alone would shuffle
// them together.
const teamsSQL = `
SELECT t.id, t.name, t.abbr, t.crest_url, s.rank, s.played, s.points
FROM standing s
JOIN team t ON t.id = s.team_id
WHERE s.comp_id = $1 AND s.season_id = $2
ORDER BY COALESCE(s.group_name, ''), s.rank, t.id`

func (s *Store) Teams(ctx context.Context, competition, season string) ([]TeamSummary, error) {
	rows, err := s.db.Query(ctx, teamsSQL, competition, season)
	if err != nil {
		return nil, err
	}
	defer rows.Close()

	teams := make([]TeamSummary, 0)
	for rows.Next() {
		var team TeamSummary
		if err := rows.Scan(
			&team.Team.ID, &team.Team.Name, &team.Team.Abbr, &team.Team.CrestURL,
			&team.Rank, &team.Played, &team.Points,
		); err != nil {
			return nil, err
		}
		teams = append(teams, team)
	}
	return teams, rows.Err()
}

// A club belongs to a competition season if any one of three facts holds: it has
// a table row, it has an ingested season record, or it appears in a fixture. All
// three are needed - a knockout-only entrant has no standing row, and a club we
// have fixtures for but have not profiled yet has no team_season row. If none
// hold, the row does not exist and the caller gets ErrNotFound rather than a
// profile made entirely of nulls, which would assert that América are in a
// competition they have never entered.
const teamProfileSQL = `
SELECT t.id, t.name, t.abbr, t.crest_url,
       t.location, t.color, t.alternate_color, t.venue_name,
       ts.standing_summary, ts.record_summary,
       s.rank, s.played, s.wins, s.draws, s.losses,
       s.goals_for, s.goals_against, s.goal_difference, s.points, s.advanced
FROM team t
LEFT JOIN team_season ts
  ON ts.team_id = t.id AND ts.comp_id = $1 AND ts.season_id = $2
LEFT JOIN standing s
  ON s.team_id = t.id AND s.comp_id = $1 AND s.season_id = $2
WHERE t.id = $3
  AND (
    ts.team_id IS NOT NULL
    OR s.team_id IS NOT NULL
    OR EXISTS (
      SELECT 1 FROM match m
      WHERE m.comp_id = $1 AND m.season_id = $2
        AND $3::text IN (m.home_team_id, m.away_team_id)
    )
  )`

func (s *Store) TeamProfile(ctx context.Context, competition, season, teamID string) (*TeamProfile, error) {
	var profile TeamProfile
	var rank, played, wins, draws, losses *int
	var goalsFor, goalsAgainst, goalDifference, points *int
	var advanced *bool
	if err := s.db.QueryRow(ctx, teamProfileSQL, competition, season, teamID).Scan(
		&profile.Team.ID, &profile.Team.Name, &profile.Team.Abbr, &profile.Team.CrestURL,
		&profile.Location, &profile.Color, &profile.AlternateColor, &profile.VenueName,
		&profile.StandingSummary, &profile.RecordSummary,
		&rank, &played, &wins, &draws, &losses,
		&goalsFor, &goalsAgainst, &goalDifference, &points, &advanced,
	); err != nil {
		if errors.Is(err, pgx.ErrNoRows) {
			return nil, ErrNotFound
		}
		return nil, err
	}

	// Every standing column is NOT NULL, so the LEFT JOIN is all-or-nothing: a
	// non-nil rank means the row matched and the rest matched with it. The
	// helpers below exist so a future nullable column cannot turn this into a
	// nil dereference in production.
	if rank != nil {
		profile.Standing = &Standing{
			Team:           profile.Team,
			Rank:           *rank,
			Played:         intValue(played),
			Wins:           intValue(wins),
			Draws:          intValue(draws),
			Losses:         intValue(losses),
			GoalsFor:       intValue(goalsFor),
			GoalsAgainst:   intValue(goalsAgainst),
			GoalDifference: intValue(goalDifference),
			Points:         intValue(points),
			Advanced:       advanced != nil && *advanced,
		}
	}

	// The next fixture is derived from match rows we already hold rather than
	// from ESPN's nextEvent, so it can never disagree with what /matches says
	// about the same fixture. Reusing MatchFilter here is the second reason it
	// grew a TeamID: one query shape serves both callers.
	//
	// "Next" means the earliest *scheduled* fixture. A match in progress is not
	// a next match, and a caller that wants it asks /teams/{id}/matches?state=live.
	one := 1
	next, err := s.Matches(ctx, competition, season, MatchFilter{
		TeamID: teamID,
		State:  string(espn.MatchStateScheduled),
		Order:  "asc",
		Limit:  &one,
	})
	if err != nil {
		return nil, err
	}
	if len(next) == 1 {
		profile.NextMatch = &next[0]
	}
	return &profile, nil
}

func intValue(value *int) int {
	if value == nil {
		return 0
	}
	return *value
}
```

```go
// order that looks intentional and means nothing, which is the same defect class
// as ranking a table alphabetically. A caller that wants positional grouping has
// the position on every row and can order it with real football knowledge.
const squadSQL = `
SELECT player_id, player, position, jersey, stats
FROM squad_player
WHERE comp_id = $1 AND season_id = $2 AND team_id = $3
ORDER BY player, player_id`

func (s *Store) Squad(ctx context.Context, competition, season, teamID string) ([]SquadPlayer, error) {
	rows, err := s.db.Query(ctx, squadSQL, competition, season, teamID)
	if err != nil {
		return nil, err
	}
	defer rows.Close()

	players := make([]SquadPlayer, 0)
	for rows.Next() {
		var player SquadPlayer
		var stats []byte
		if err := rows.Scan(
			&player.PlayerID, &player.Player, &player.Position, &player.Jersey, &stats,
		); err != nil {
			return nil, err
		}
		// Every PlayerSeasonStats field is a *float64 and the blob only carries
		// the keys ESPN sent, so a statistic that does not apply to this player's
		// position has nowhere to land and stays nil. There is no defaulting code
		// here on purpose: the only way to turn an absent statistic into a zero
		// would be to write one.
		if err := jsonInto(stats, &player.Stats); err != nil {
			return nil, err
		}
		players = append(players, player)
	}
	if err := rows.Err(); err != nil {
		return nil, err
	}
	// Not []. A football club always has players; an empty result means we have
	// not ingested the roster, and a caller must be able to tell that apart from
	// a squad of nobody.
	if len(players) == 0 {
		return nil, ErrNotFound
	}
	return players, nil
}
```

```go
package main

import (
	"errors"
	"net/http"

	"github.com/go-chi/chi/v5"

// teamPathParams runs every guard these routes share, in the order that costs
// the least: the registry check needs no allocation, the id check needs no
// dependency, and neither touches the database. A request that fails either has
// already spent one rate-limit token, and it must not also spend a query.
func (a *App) teamPathParams(writer http.ResponseWriter, request *http.Request) (competition, season, teamID string, ok bool) {
	competition = chi.URLParam(request, "comp")
	season = chi.URLParam(request, "season")
	if _, _, resolved := a.resolve(competition, season); !resolved {
		writeError(writer, http.StatusBadRequest, "unknown competition or season")
		return "", "", "", false
	}
	teamID, err := parseEntityID(chi.URLParam(request, "teamId"))
	if err != nil {
		// Safe to echo: every error out of params.go is a constant declared
		// there, never a wrapped dependency error.
		writeError(writer, http.StatusBadRequest, err.Error())
		return "", "", "", false
	}
	return competition, season, teamID, true
}

func (a *App) handleTeams(writer http.ResponseWriter, request *http.Request) {
	competition := chi.URLParam(request, "comp")
	season := chi.URLParam(request, "season")
	if _, _, ok := a.resolve(competition, season); !ok {
		writeError(writer, http.StatusBadRequest, "unknown competition or season")
		return
	}
	teams, err := a.store.Teams(request.Context(), competition, season)
	if err != nil {
		a.logger.Error("teams", "competition", competition, "season", season, "err", err)
		writeError(writer, http.StatusInternalServerError, "internal error")
		return
	}
	if teams == nil {
		teams = []TeamSummary{}
	}
	cacheFor(writer, 60)
	writeJSON(writer, http.StatusOK, teams)
}

func (a *App) handleTeamProfile(writer http.ResponseWriter, request *http.Request) {
	competition, season, teamID, ok := a.teamPathParams(writer, request)
	if !ok {
		return
	}
	profile, err := a.store.TeamProfile(request.Context(), competition, season, teamID)
	if errors.Is(err, ErrNotFound) || (err == nil && profile == nil) {
		// The nil check is not redundant: Store returns ErrNotFound, but the
		// interface allows a nil profile with a nil error and a 200 carrying
		// "null" would be a worse answer than a 404.
		writeError(writer, http.StatusNotFound, "team not found in this competition season")
		return
	}
	if err != nil {
		a.logger.Error("team profile", "competition", competition, "season", season, "team", teamID, "err", err)
		writeError(writer, http.StatusInternalServerError, "internal error")
		return
	}
	// The profile's next fixture is by definition scheduled, never live, so this
	// tracks the standard cadence rather than the ten-second live one.
	cacheFor(writer, 60)
	writeJSON(writer, http.StatusOK, profile)
}

func (a *App) handleSquad(writer http.ResponseWriter, request *http.Request) {
	competition, season, teamID, ok := a.teamPathParams(writer, request)
	if !ok {
		return
	}
	players, err := a.store.Squad(request.Context(), competition, season, teamID)
	if errors.Is(err, ErrNotFound) || (err == nil && len(players) == 0) {
		// Not an empty array. An empty squad would claim a football club has no
		// players; what an empty result actually means is that we have not
		// ingested the roster.
		writeError(writer, http.StatusNotFound, "squad not available for this team")
		return
	}
	if err != nil {
		a.logger.Error("squad", "competition", competition, "season", season, "team", teamID, "err", err)
		writeError(writer, http.StatusInternalServerError, "internal error")
		return
	}
	cacheFor(writer, 60)
	writeJSON(writer, http.StatusOK, players)
}

func (a *App) handleTeamMatches(writer http.ResponseWriter, request *http.Request) {
	competition, season, teamID, ok := a.teamPathParams(writer, request)
	if !ok {
		return
	}
	filter, err := parseMatchFilter(request)
	if err != nil {
		writeError(writer, http.StatusBadRequest, err.Error())
		return
	}
	filter.TeamID = teamID
	matches, err := a.store.Matches(request.Context(), competition, season, filter)
	if err != nil {
		a.logger.Error("team matches", "competition", competition, "season", season, "team", teamID, "err", err)
		writeError(writer, http.StatusInternalServerError, "internal error")
		return
	}
	// [] here, unlike the squad above: a club with no fixtures in a window is a
	// real answer - the fixtures are not published yet, or the window is out of
	// season. A caller distinguishing that from a wrong id asks /teams/{teamId},
	// which 404s.
	writeMatches(writer, matches)
}
```

```markdown
## Team endpoints

| Endpoint | Returns | Cache-Control |
|---|---|---|
| `/v1/competitions/{comp}/{season}/teams` | every club with a table row, in table order | `public, max-age=60` |
| `/v1/competitions/{comp}/{season}/teams/{teamId}` | one club's profile inside this competition | `public, max-age=60` |
| `/v1/competitions/{comp}/{season}/teams/{teamId}/squad` | one row per athlete with season statistics | `public, max-age=60` |
| `/v1/competitions/{comp}/{season}/teams/{teamId}/matches` | that club's fixtures; takes `range`, `state`, `order`, `limit` | `public, max-age=10` live, else `60` |

Every team route is competition-scoped. A club's record only means something
inside a competition, and the same club appears in several at once — América are
in Liga MX and the Leagues Cup simultaneously with different records in each.

**Null is not zero.** Every field in `PlayerSeasonStats` is nullable and `null`
means the provider sent no such statistic for that player, usually because it
does not apply to the position. A goalkeeper's `offsides` is `null`; a
forward's `saves` is `null`; a forward's `redCards` of `0` is a real zero.
Render `null` as a dash, never as `0`.

athlete and it is empty for all of them. An `injuries: []` in this API would tell
you the squad is fit, which we do not know.

there is nothing to return, because "no clubs yet" and "no fixtures in this
window" are real answers. `/teams/{id}` and `/squad` return `404` instead: a
profile of nulls would assert a club is in a competition it never entered, and an
empty squad would assert a football club has no players.
```

## Self-review notes

- **Spec coverage.** E4's header (crest, name, location, record, standing
  summary, club colours) → `TeamProfile` in Task 3. E4's "form and next fixture"
  → `NextMatch` plus `/teams/{id}/matches?state=finished&order=desc&limit=5`,
  which is why `desc`+`limit` had to keep working through the placeholder
  renumbering. E4's squad statistics table → Task 4. E4's fixtures & results
  block → `/teams/{id}/matches`. E4's "same nullability rule as E1: a dash, never
  a zero" → the entire design of `PlayerSeasonStats`.
- **The nullability rule is enforced three times, deliberately.** In the schema
  (`jsonb`, no per-stat columns with defaults), in the Go type (`*float64`), and
  on the wire (`TestSquadNullabilitySurvivesToJSON` asserts literal bytes). Two of
  those would be enough to be correct; three are what stops a later refactor from
  quietly reintroducing the defect, because a change that breaks the rule fails a
  test that names the rule.
- **Shared-symbol churn.** `MatchFilter` gains `TeamID`, `matchOrderSQL`'s two
  values renumber `LIMIT` to `$7`, `Store.Matches`'s argument list gains one
  entry, `readerStore` gains three methods, and `handleMatches` loses its tail to
  `writeMatches`. The sibling `api-*` plans all touch `server.go`, `types.go` and
  `openapi.yaml`, so they should land one at a time rather than in parallel.
- **Deliberately not built: a cross-competition team page.** "América everywhere"
  needs identity resolution across competitions and is out of scope per the E4
  spec. Every route here takes a competition and a season for that reason, and
  `TeamProfile` is explicitly a club *inside* a competition rather than a club.
- **Deliberately not built: an injuries endpoint.** Stated three times in this
  plan on purpose — in the ingester prerequisites, in the OpenAPI description,
  and in the README — because the tempting mistake is not building the feature,
  it is adding an `injuries: []` field "for completeness" and shipping a claim.
- **Named follow-up, not a silent omission.** The four numeric `team_season`
  columns are written and not read. They are in the migration because the
  ingester slice needs somewhere to put `record.items[]`, and because a
  `"3-0-0"` string with no numbers behind it cannot be checked against the table.
  Serving them belongs to E9's next team slice; it is in the PR body so it does
  not become archaeology.
- **Cost.** One squad request serves 35 players from one row set, and the roster
  behind it costs the ingester one upstream request, not 35 — the single biggest
  reason this slice is worth building now rather than after E5. The `/teams` list
  exists so a client does not download a full standings response (eleven extra
  fields per row) just to learn which ids exist.
- **Ordering choices are both defensive.** `/teams` orders by group then rank so
  two clubs ranked 1 in different groups do not interleave; `/squad` orders by
  player name rather than position code, because position codes sort to D, F, G,
  M — an order that looks intentional and means nothing, which is the same defect
  class as E0's alphabetical champion.
